**Goal:** Add `PostgresBackendLock` to the Dhara substrate, mirroring `SQLBackendLock` (DuckDB) but using `asyncpg` + Postgres-native `$N` placeholders and Postgres conflict exception types. Ship as a public primitive alongside the existing `InMemoryDharaLock` and `SQLBackendLock` so production deployments can pick.

**Architecture:** New `dhara/lock/postgres.py` module exposes `PostgresBackendLock(asyncpg_conn)` following the `DharaLock` Protocol. SQL strings use `$1, $2, ...` numbered placeholders. Exception handler translates `asyncpg.SerializationError` (`SQLSTATE 40001`) and `asyncpg.DeadlockDetected` (`SQLSTATE 40P01`) to `LockLost`. Schema additions go to the existing `dhara/storage/pg_schema.sql` — `substrate_locks` table + indexes. Public API export in `dhara/lock/__init__.py`. **No DharaMCPServer wiring required** — locks are primitives, not auto-selected by storage backend.

**Tech Stack:** Python 3.13, msgspec.Struct, **asyncpg 0.31.0** (already in pyproject.toml), pytest-asyncio, no new third-party deps.

## Context

D-LOCK v1 (shipped 2026-08-04) implemented `SQLBackendLock` in `dhara/lock/sql.py` using DuckDB-style `?` placeholders and `duckdb.TransactionException`. The module docstring at `dhara/lock/sql.py:18-19` explicitly defers Postgres translation: "Postgres translation (named placeholders / $N) is future work; v1 uses DuckDB-style `?` placeholders."

v1.1 closes this gap by adding a parallel `PostgresBackendLock` that:

- Uses Postgres-native `$N` numbered placeholders (required by asyncpg)
- Handles Postgres-specific conflict exceptions (`asyncpg.SerializationError`, `asyncpg.DeadlockDetected`)
- Lives alongside `SQLBackendLock` as a separate class so the DuckDB implementation is unchanged
- Is exported from `dhara.lock` so call sites can import it directly

The Postgres schema (`dhara/storage/pg_schema.sql`) already exists for `dhara_objects` and `dhara_dirty_oids`. v1.1 ADDS a `substrate_locks` table to that file (no new migration file — `pg_schema.sql` IS the runtime schema for Postgres deployments, mirroring how `dhara/migrations/sql/0003_locks.sql` IS the DuckDB runtime schema).

## Global Constraints

- Use `asyncpg` (NOT psycopg2) — asyncpg is the installed dep at pyproject.toml:20.
- Use `$1, $2, ...` numbered placeholders in ALL SQL strings (Postgres native).
- Translate `asyncpg.SerializationError` AND `asyncpg.DeadlockDetected` to `LockLost`. Both carry `SQLSTATE` codes (`40001` and `40P01` respectively).
- `from __future__ import annotations` first non-comment line in all source files.
- Imports sorted stdlib → third-party → first-party (`known-first-party = ["dhara"]`).
- `X | None = None` (no implicit Optional).
- No `assert` in production code (`dhara/lock/postgres.py`).
- Use `from oneiric.core.logging.get_logger` (not stdlib logging).
- NEVER log `str(exception)` — log `type(exception).__name__` only.
- TDD: RED → GREEN → REFACTOR.
- Bodai pre-1.0 merge policy: commits to `main` directly.
- **No DharaMCPServer wiring.** The lock layer is independent of the storage layer; callers select the backend at construction time.

# Postgres SQLSTATE codes for the two conflict types we translate to LockLost.
_PG_SERIALIZATION_FAILURE = "40001"
_PG_DEADLOCK_DETECTED = "40P01"


class AsyncpgConn(Protocol):
    """Minimal asyncpg.Connection contract.

    Mirrors dhara.lock.sql.SQLBackend but typed for asyncpg. The wrapper
    must adapt the asyncpg.Connection to a uniform async interface.

    async def fetch(self, sql: str, *args: Any) -> list[Any]: ...
    async def fetchrow(self, sql: str, *args: Any) -> Any: ...

def _is_postgres_conflict(exc: Exception) -> bool:

    sqlstate = getattr(exc, "sqlstate", None) or getattr(exc, "pgcode", None)
    return sqlstate in (_PG_SERIALIZATION_FAILURE, _PG_DEADLOCK_DETECTED)
