# D-AUDIT — Layer 0 AuditLog substrate (completion report, 2026-08-10)

## Status: SHIPPED → WIRED → ADOPTED

D-AUDIT is wired through `DharaMCPServer`; the cross-system integration test exercises the
full `dhara.put` → audit outbox → `audit_log` → query path.

## What shipped

- Migration 0004 — `audit_log` table (BIGINT id, entity_type, entity_id,
  recorded_at TIMESTAMPTZ, payload TEXT) plus the entity_type_recorded_at index.
- `dhara/audit/subscriber.py` — `AuditLogSubscriber` validates `audit_record` through
  `SCHEMA_REGISTRY`, enqueues into `MemoryOutbox`, and preserves the G6 failure contract.
- `dhara/audit/outbox.py` — `MemoryOutbox`, a bounded FIFO with drop-oldest overflow behavior.
- `dhara/audit/flusher.py` — `OutboxFlusher` asynchronously drains records into `audit_log`.
- `dhara/audit/query_tool.py` — `AuditLogQueryTool` reads records through `from_dict` with
  schema validation.
- `dhara/mcp/server_core.py` — `DharaMCPServer` registers the subscriber and query routes via
  `register_audit_routes`.

## Trigger path

`OutboxFlusher.flush` → `audit_log`.

## Integration point

`audit_log` table and are returned by `AuditLogQueryTool.query`.
